`NodeFilesApi.write` streams: chunks go (batched to 64 KiB) to a temporary file beside the target, which is renamed over the target once the content has ended. Memory stays at about two 64 KiB batches plus one chunk instead of the whole file, a source that fails leaves the old file in place, and a file can be rewritten from its own `read`. A read-only file or a directory is refused before the source is read. Replacing keeps the old file's permission bits (setuid/setgid are dropped, as a write would clear them) and writes through a symbolic link to its target; a dangling link is replaced by a regular file, a hard link is replaced rather than written through, and owner, ACLs and extended attributes are those of a new file. Temporaries are named `.webrun-tmp-` plus 16 hex digits; `list` hides files with exactly that name, and a crash can leave one behind. `write("/")` is refused. Also fixed: a `NodeFilesApi` rooted at `/` refused every path. The disk must hold the old and the new file until the rename, and the content is not fsynced before it. On Windows a rename refused because the file is open elsewhere is retried for about a second; a bind-mounted file or one on another device (`EBUSY`, `EXDEV`) is written in place by copying the temporary into it (keeping its owner and mode; a failure part way leaves it partial).
